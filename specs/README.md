# Repository Contracts

Purpose: repository-wide machine contracts spanning more than one Sandbox component.

Owner: SDKWork Runtime Platform maintainers.

`sandbox-commercial-readiness.contract.json` is the active fail-closed release assessment for the complete BirdCoder -> Agents -> Kernel -> Sandbox workflow. It separates stable ownership and lifecycle invariants from replaceable Provider, storage, transport, node, and Secret adapters; records Local, cold Firecracker, Pool, cross-repository, and operations slices; and makes missing ready contracts explicit. Its current decision is `no-go`. Passing Gate 0 contract tests is not runtime or commercial evidence.

`sandbox-internal-control-plane.contract.json` is the draft Kernel-to-Sandbox service-boundary authority. It proposes one Sandbox application port with in-process standalone and generated internal-RPC cloud adapters, L3 service identity, durable operation/idempotency behavior, independent Kernel/Sandbox fencing, bounded operation-event observation, version fail-close, discovery, drain and rollout gates. It does not authorize a Rust Port, Proto, SDK, server/client, HTTP route, discovery registration, config, deployment or Kernel change.

`sandbox-interactive-terminal-session.contract.json` is the draft IDE Terminal authority. It separates non-interactive Command from Interactive Terminal capability evidence and defines a subordinate Terminal Session, single-controller lease, at-most-once input, idempotent resize, ordered bounded output replay, reconnect grace, first-terminal CAS, Workspace freeze/checkpoint ordering, exact platform containment and privacy gates. It does not authorize capability names, PTY/ConPTY, process spawn, guest-agent streaming, Proto/SDK/API, persistence, Provider, Service Host, deployment or cross-repository code.

`sandbox-runtime-secret-projection.contract.json` is the draft credentialed-execution authority. It keeps cross-repository contracts value-free; separates Agents/IAM/Secret Authority/Kernel/Sandbox ownership; binds opaque post-placement grants to Runtime, fencing, audience, lane and region; constrains process projection targets; and defines rotation, revocation, outage, Checkpoint exclusion, pool non-reuse, audit and scoped claims. It does not authorize a Secret Manager/KMS/Keychain, value transport, process projection, Host Broker/guest-agent operation, Proto/SDK/API, persistence, Provider, Service Host, deployment or cross-repository code.

`sandbox-cloud-data-residency.contract.json` is the draft Cloud data authority. It inventories Workspace/Revision/Checkpoint, runtime/control, output, logs, caches, usage, backups and DR copies; separates SDKWork, provider, storage and failure-domain regions; preserves Agents/Drive/Sandbox ownership; and defines explicit replication, PITR, restore, export/delete, tenant isolation, Secret exclusion and fail-closed recovery gates. It does not authorize a region, storage adapter, replication, backup/PITR worker, restore/purge controller, API/SDK, config, deployment or cross-repository code.

`sandbox-cross-repository-version-compatibility.contract.json` is the draft release-compatibility authority. It fixes an immutable BirdCoder/Agents/Kernel/Sandbox release set plus Workspace/storage, RPC/Proto, generated SDK, runtime config, provider/artifact and evidence provenance; requires multi-dimensional compatibility, peer preflight before side effects, staged rollout/drain, migration-aware rollback, downgrade denial and bounded support windows. It does not authorize a release registry, SDK/proto/artifact publication, migration, deployment or cross-repository code.

`sandbox-provider-delivery-gates.contract.json` is the draft cross-component Gate 0 authority for the Local/Command/Firecracker delivery sequence. It fixes provider-neutral conformance, Local `HostUser` limits, Firecracker `MicroVm` preflight requirements, forbidden fallbacks, and required human review evidence; `implementationAuthorized` remains `false`.

`sandbox-local-provider-host-boundary.contract.json` is the draft Local Host Boundary authority for standalone `HostUser` execution. It fixes opened-capability ownership, handle-relative filesystem containment, Windows suspended Job Object supervision, Linux race-free delegated cgroup v2 membership, explicit macOS Terminal denial, empty-allowlist environment construction, bounded cleanup/quarantine, private-data observability, conditional dependency candidates and real-runner evidence. It does not authorize a public Port, Host I/O, process spawn, Secret injection, runtime dependency change, deployment profile or isolation claim.

`sandbox-host-isolation-broker.contract.json` is the draft cross-component privileged-host boundary for fixed typed operations, local IPC, short-lived grants, privilege constraints, fencing/idempotency, readiness, safe results, audit, and bounded cleanup. It does not authorize a Broker component, daemon, socket, service unit, privileged operation, or deployment profile.

`sandbox-firecracker-artifact-compatibility.contract.json` is the draft Firecracker Artifact Gate 0 authority for the immutable architecture-specific `SandboxFirecrackerArtifactManifest`, exact artifact roles, release evidence, fail-closed node materialization, revocation, rollback, readiness, and ownership. `sandbox-standalone-data-residency.contract.json` is the draft Local commercial data-residency Gate 0 authority. It separates device-local persistence from strict device-local processing, inventories eleven BirdCoder/Agents/Kernel/Sandbox data classes, preserves server PostgreSQL versus declared client-local SQLite roles, requires distinct Workspace/data/runtime/cache/log/secret/temp capabilities, denies implicit remote storage/sync/backup/telemetry, preserves Workspace during cleanup/reset/uninstall, and fixes backup/restore/export/purge/failure evidence. It applies only to `sandbox_standalone_local`; it does not create a store, path, migration, backup, purge, telemetry, sync, API/SDK, config, package, deployment or cross-repository source change.

`sandbox-real-evidence-registry.json` is the draft real-evidence producer authority. The other contracts in this directory name 127 evidence ids they require before a Provider may be implemented, and nothing previously declared who or what produces any of them; a required piece of evidence with no producer cannot fail a test, it simply never happens. The registry snapshots every required evidence id per contract, records the two ids for which `tools/testing/sandbox-host-capability-evidence.mjs` produces a host-precondition half, and makes the 125 ids that remain fully gated by a real runner or human review an explicit, drift-checked number. It does not authorize a Provider, Provider Port, API route, HTTP route, SDK, scheduler, isolation policy, secret injection, deployable profile, runtime dependency change, process spawn, host I/O, public port, cgroup, namespace, netns, Tap, firewall, or `MicroVm`, and neither it nor any host fact is conformance or commercial evidence. `tools/check-sandbox-evidence-traceability.mjs` enforces it.

`sandbox-e2b-capability-baseline.json` is the captured E2B capability-baseline authority. It records, per source, the exact E2B documentation surface this repository measures alignment against — the public OpenAPI document at `https://docs.e2b.dev/openapi-public.yaml`, the documentation page index, and every fetched documentation page — each with its `url`, `sha256`, `bytes` and `kind`, together with the 17 audit categories and all 78 alignment rows, each carrying the E2B fields, CLI grammar and documentary facts that row was verified against. Its `sha256` values are provenance statements recorded at capture time, not offline-verifiable digests, and `recaptureCommand` describes how to re-capture them. It also carries a ratchet (`maxIndexOnlyRows`) that forbids any row from regressing to a documentation-index-only judgement. It records what E2B's surface is; it does not authorize a Provider, Provider Port, API route, HTTP route, SDK, scheduler, isolation policy, secret injection, deployable profile or any runtime change, and it is not conformance, runtime or commercial evidence. `tools/check-sandbox-e2b-field-parity.mjs` enforces it.

Component contracts live beside each crate at `crates/<crate>/specs/component.spec.json`. Future topology, deployment, or composition manifests may be added here only when they are the machine source of truth.

Global standards remain at `../../sdkwork-specs/`; do not copy their bodies into this directory.
